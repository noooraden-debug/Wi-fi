# WiFi Hub — تحكّم كامل بالراوتر: بلا root، بلا سيرفر

التطبيق يتصل **مباشرة** براوتر OpenWrt عبر `ubus` من داخل الشبكة، والملف الوحيد المطلوب
هو `hub.json` المنشور على GitHub. لا حاجة لأي خادم يعمل، ولا لأي أمر تقني من المشترك.

---

## 1) ما الذي بُني بالضبط

| المكوّن | الموقع | الدور |
|---|---|---|
| محرك ubus | `web/js/ubus.js` | تسجيل جلسة، نداء `session`/`uci`/`file`/`hostapd` |
| طبقة التحكم | `web/js/router.js` | اكتشاف الراوتر، الأجهزة، الحظر/التجميد، تغيير الواي فاي |
| مدير الإعدادات | `web/js/config.js` | قراءة/كتابة `hub.json` من GitHub مع نسخة محفوظة عند انقطاع الإنترنت |
| الحسابات والاشتراكات | `web/js/accounts.js` | الأكواد، المشتركون، الطلبات، الكتابة عبر GitHub API |
| الواجهة | `web/index.html` + `web/css/app.css` | تطبيق عربي RTL |
| التطبيق الأصلي | `android/` | جسر HTTP يتجاوز CORS + اكتشاف البوابة تلقائياً |
| أدوات الإدارة | `tools/` | CLI لإدارة الملف، راوتر وهمي، اختبارات |

### لماذا تطبيق أصلي وليس متصفحاً؟
في OpenWrt، نقطة `http://<router>/ubus` ترفض طلبات المتصفح العابرة للمصدر (CORS)
إلا إذا فعّل المالك `ubus_cors=1` داخل `uhttpd` — وهذا **يتطلب root**، وهو ما طلبت تجنّبه.
لذلك: التطبيق الأصلي (Android) يطلب `ubus` مباشرة دون قيود CORS، **بلا root وبلا سيرفر**.

## 1أ) المسار الأسرع: لا بناء محلي ولا تشغيل خادم

 pushing الكود إلى مستودع GitHub كافٍ — GitHub Actions يتولّى الباقي:

| الملف | ما يفعله تلقائياً |
|---|---|
| `.github/workflows/build-apk.yml` | يبني `wifihub.apk` عند كل رفع ويصدره في **Releases** باسم `app` |
| `.github/workflows/auto-activate.yml` | يسجّل طلب الاشتراك في `hub.json` ويغلق الـ Issue (بدون تفعيل) |
| `.github/scripts/activate.js` | منطق التفعيل: كود صالح ⇒ تفعيل + وسم الكود، وإلا ⇒ pending بانتظار موافقة المالك |

دورة العمل: **المشترك يطلب (زر واحد) → المالك يضغط «تفعيل» → المشترك يستخدم كل المميزات تلقائياً.**
الرابط النهائي للمشتركين: `https://github.com/<OWNER>/<REPO>/releases/tag/app`

**لا يوجد اشتراك تلقائي:** الطلب يُسجَّل فقط، والمالك هو من يعتمد من «لوحة الإدارة»
بضغطة **«✅ تفعيل»** واحدة — ثم تُفتح كل المميزات لدى المشترك تلقائياً خلال ≤30 ثانية.
(إن أردت التفعيل الآلي لاحقاً: `"autoApprove": true` في `hub.json`.)

> إن كان المستودع خاصاً، أضف في GitHub ← Settings ← Secrets:
> `WIFIHUB_CONFIG_URL` (رابط hub.json) · `WIFIHUB_READ_TOKEN` · `WIFIHUB_REQUEST_TOKEN`
> (توكن Issues فقط لإنشاء طلبات الاشتراك). بدونها يعمل البناء برابط افتراضي يُعدَّل في `config/app.json`.

## 3) بناء التطبيق (مرة واحدة) وإعطاؤه للمشتركين

```bash
# 1) ضع رابط الإعدادات (وأي توكنات) في ملف الإعدادات
vim config/app.json   # أو: GitHub Secret باسم WIFIHUB_CONFIG_URL
{
  "configUrl": "https://raw.githubusercontent.com/<OWNER>/<REPO>/main/hub.json",
  "readToken": "",
  "requestToken": ""
}

# 2) ابنِ الـ APK (لا يحتاج Gradle ولا Android Studio)
cd android && ANDROID_HOME=/path/to/android-sdk ./build.sh

# 3) النتيجة:
android/dist/wifihub.apk
```

> **لماذا يُطلب `requestToken`؟** ليرسل المشترك طلب اشتراكه تلقائياً إلى GitHub
> Issues، يحتاج التطبيق **توكناً محدود الصلاحية** على Issues فقط داخل هذا المستودع
> (أو فعّل `autoApprove` وتخطَّ الطلبات ووافق من لوحة الإدارة).
> Permissions: `Issues: Read & write` على هذا المستودع فقط — **لا** تعطِ صلاحيات أخرى.

يختار المشترك التطبيق ويشترك فوراً — لا حساب ولا خادم ولا إعداد.

## 3أ) الفئات: مجاني / بريميوم + دخول الإدارة مُشفَّر

| الفئة | ماذا يرى |
|---|---|
| **مجاني** (سجّل بلا اشتراك) | لوحة تحكم بسيطة + الباقات. **الأجهزة المتصلة مقفلة، وتغيير كلمة مرور الواي فاي مقفل، وكل المميزات مقفلة.** |
| **بريميوم** (بعد تفعيل كود) | كل المميزات مفتوحة + **عداد الأيام المتبقية من باقته** + تغيير كلمة مرور الراوتر بنفسه |

**دخول الإدارة:** الاسم `admin` وكلمة المرور `admin` (غيّرها فوراً).
كلمة المرور مخزَّنة **مُشفَّرة** في `hub.json` بصيغة `app.admin = { username, salt, hash }`
(SHA-256 + salt) — لا تُخزَّن كنص صريح أبداً. لتغييرها:
- من داخل التطبيق: «الإدارة ← بيانات دخول الإدارة» (تُحفظ مُشفَّرة مباشرة على GitHub)، أو
- من الطرفية: `node tools/hub-cli.mjs admin hub.json --user NAME --pass SECRET`

## 4) رحبة المشترك (صفر خطوات تقنية)

1. يفتح التطبيق (من APK) → يقرأ `hub.json` تلقائياً (الرابط مدمج عند البناء).
2. ينشئ حسابه باسم وكلمة مرور (على جهازه) أو يدخل بحسابه.
3. يطلب الباقة (زر واحد) أو يدخل الكود الذي وصلك — **لا يدخل الراوتر ولا يرى أي إعدادات**.
4. يتصل التطبيق **تلقائياً** بالراوتر (يكتشف البوابة من الهاتف ثم يجرّب عناوين شائعة).
5. فور اعتماد المالك للطلب (≤30 ثانية) تظهر أجهزته واستهلاكها وتُفتح كل المميزات.
   أثناء الانتظار تظهر رسالة «طلبك قيد المراجعة» وزر «تحديث الحالة».

**المشترك لا يرى أبداً:** اسم مستخدم الراوتر، كلمة مرور الراوتر، عناوين IP، أو أي حقل تقني —
كلها داخل `hub.json` الذي يقرأه التطبيق وحده.

## 4أ) دورة الاشتراك الكاملة (كما يطلب الزبون)

1. الزبون يختار الباقة (شهري / 3 أشهر / 6 أشهر / سنة) ويضغط «📲 اطلب الباقة».
2. **الواتساب يفتح تلقائياً على الرقم 963957869853** برسالة مميزة جاهزة:
   ```
   *طلب اشتراك WiFi Hub*
   ━━━━━━━━━━━━━━━
   📦 الباقة: سنة
   👤 الاسم: ahmad
   📅 التاريخ: 8/11/2026
   ━━━━━━━━━━━━━━━
   أرسل لي كود التفعيل وسأدخله في البرنامج.
   ```
3. أنت تولّد كوداً من لوحة الإدارة (باقة + عدد أجهزة + تاريخ انتهاء) — **25 خانة عشوائية
   آمنة** (`WH-XXXXX-XXXXX-XXXXX-XXXXX` ≈ 125 بت) يصعب تخمينه.
4. ترسل له الكود (واتساب) → يدخله في البرنامج → **يتحوّل فوراً من مجاني إلى بريميوم**،
   وتُفتح كل المميزات، ويظهر له **عداد الأيام المتبقية**.
5. عند انتهاء الباقة **يعود تلقائياً إلى مجاني** وتُقفل المميزات مجدداً حتى يعيد الاشتراك.

## 5) رحبة المالك (لوحة الإدارة داخل التطبيق)

- **📨 طلبات الاشتراك**: تظهر من Issues تلقائياً → زر «✅ تفعيل» يكفي (يمدّد الاشتراك
  ويكتب اسم المشترك في `hub.json`).
- **🔑 الأكواد**: توليد أي عدد (10/50/…) مع باقة وعدد أجهزة وتاريخ انتهاء، ثم نسخ أو
  تصدير CSV لمشاركتها عبر واتساب. الأكواد عشوائية آمنة (25 خانة) وتُحفظ في `hub.json`.
- **👥 المشتركون**: تمديد 30/90 يوماً، حذف، متابعة الأجهزة.
- **🔧 الراوتر**: العنوان، المستخدم، كلمة المرور، رقم واتساب، التفعيل التلقائي، إعادة التشغيل.
- كل تعديل يُكتب **مباشرة على GitHub**، فيصل لكل المشتركين خلال دقيقة (Poll كل 60 ثانية).

## 6) كيف يتم التحكم فعلياً (آلية العمل)

| العملية | التنفيذ على OpenWrt | النتيجة |
|---|---|---|
| جلب الأجهزة | `file read /etc/dhcp.leases` + `hostapd.*.get_clients` | الاسم، MAC، IP، الإشارة، الاستهلاك |
| حظر جهاز | قاعدة `firewall` (سطر `src_ip` + `REJECT`) + تثبيت `dhcp` host + `hostapd del_client` | يمنع الاتصال ويبقى بعد إعادة تشغيل الراوتر |
| تجميد | نفس الحظر مع وقت انتهاء في التطبيق | فك تلقائي عند انتهاء المدة |
| رفع الحظر | حذف القاعدة من `uci` + إعادة تحميل الجدار | عودة الجهاز للاتصال |
| تغيير اسم الشبكة/كلمة المرور | `uci set` (تشفير WPA2 تلقائياً عند الحاجة) + `uci commit` + `wifi reload` | تغيير فوري |
| تدوير الشبكة | اسم + كلمة مرور عشوائية | قطع جميع الأجهزة |
| تغيير كلمة مرور دخول الراوتر | `chpasswd`/`passwd` ثم **تسجيل دخول تجريبي** للتأكيد | تغيير فوري + تحقق فعلي |
| إعادة التسمية | `dhcp` host name | اسم واضح للجهاز |
| اكتشاف الراوتر | بوابة الهاتف + قائمة عناوين شائعة | لا يحتاج المستخدم لكتابة IP |

كل هذه تنفَّذ بحساب `root` على **الراوتر** عبر جلسة ubus، وبذلك **لا يحتاج المستخدم
أي صلاحية root على جهازه، ولا يحتاج الراوتر أي تثبيت إضافي**.

## 7) الاختبارات

```bash
tools/run-test.sh        # 15 اختباراً للمحرك مقابل راوتر وهمي (ubus)
python3 tools/browser_test.py   # 10 اختبارات واجهة في متصفح حقيقي
```

الاختبار الأول يغطي: تسجيل الجلسة، قراءة اللوح، استخراج الأجهزة من DHCP وhostapd،
قراءة/تطبيق إعدادات الواي فاي، إنشاء وحذف قواعد الحظر، تثبيت IP، إعادة التسمية، ورفض
كلمة المرور الخاطئة. الثاني يغطي: تحميل الإعدادات، إنشاء الحساب، الاتصال التلقائي،
عرض الأجهزة، تغيير الواي فاي، وعرض الباقات — مع رصد أي خطأ JavaScript.

## 8) حدود يجب معرفتها

- **الراوتر يجب أن يكون OpenWrt / LEDE** (أو مشتقاً مثل FiberHome/Orange). الراوترات
  التجارية المغلقة (TP-Link/Archer الأصلية بلا فلاش OpenWrt) لا تدعم `ubus` — تحتاج
  واجهة بديلة أو استبدال الراوتر.
- **نسخة المتصفح** (من GitHub Pages) تصلح للعرض والإدارة، لكن استدعاء `ubus` منها
  سيُمنع بواسطة CORS ما لم يفعّل المالك `ubus_cors=1` (يتطلب root). النسخة الكاملة = التطبيق.
- **الدخول على الراوتر بـ root عبر الشبكة** هو نقطة الضعف الوحيدة: راعِ أن يكون
  كلمة مرور الراوتر قوية، وأن يكون `hub.json` في مستودع خاص.
- التطبيق يتصل بالراوتر **عبر الشبكة المحلية فقط** —Outside الشبكة المنزلية لن يصل.

## 9) ما يفعله المشترك بالضبط (بلا أي خطوة خارجية)

| ما يريده الزبون | كيف يتم | هل يحتاج شيئاً خارج البرنامج؟ |
|---|---|---|
| الاشتراك بباقة | يختار الباقة → يطلب (زر واحد) → المالك يضغط «تفعيل» → تُفتح المميزات تلقائياً | **لا** |
| تغيير كلمة مرور الواي فاي | حقل + «حفظ وتطبيق» | **لا** |
| التحكم بالأجهزة (حظر/تجميد/فصل/إعادة تسمية) | أزرار داخل «الأجهزة» | **لا** |
| متابعة الاستهلاك والإشارات | تلقائي عند فتح التطبيق | **لا** |
| تغيير كلمة مرور دخول الراوتر | حقل داخل تبويب «الواي فاي» (للمدير) | **لا** |

لا SSH، لا أوامر في الطرفية، لا ملفات تُرفع على الراوتر، لا تثبيت، ولا سيرفر يعمل.
